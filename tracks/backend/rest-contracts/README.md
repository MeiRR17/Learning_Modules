# REST API Contracts — Local Python Laboratory

מעבדה עצמאית לתרגול חוזי REST, קודי HTTP, ולידציה, עימוד, ניהול משאבים ו־**optimistic concurrency** בעזרת `ETag` ו־`If-Match`. המימוש משתמש **רק בספריית התקן של Python 3.10+**, ומתאים ללימוד מקומי ללא התקנת FastAPI, מסד נתונים, Docker או חשבון ענן.

המעבדה נפרדת מהקוד המיובא ב־[`tracks/backend/fastapi/`](../fastapi/) ומהפרויקט המקורי. לא שונו תרגילי ה־FastAPI, כלי התמלול או נתוני המחקר.

## 1. התחלת שרת מקומי

פתחו Terminal אחד מתיקיית המאגר:

```bash
python3 tracks/backend/rest-contracts/server.py
```

השרת מאזין **אך ורק** לכתובת `127.0.0.1:8765`. אפשר לבחור פורט 1024–65535 באמצעות `--port`. השימוש הוא מקומי בלבד; אין לפתוח את הפורט לרשת או להעביר אותו דרך tunnel ציבורי.

לא נשמר דבר לדיסק. כל המשימות נעלמות בסגירת השרת, וניתן להחזיק עד 100 משימות בכל רגע. אין משתמשים, סיסמאות, מערכת הרשאות, שירות חיצוני או טלמטריה. **אין להשתמש בשירות כמערכת משימות אמיתית או לאחסן מידע אישי.**

## 2. הפעלת לקוח הדגמה

ב־Terminal שני:

```bash
# קריאה בלבד — מחזיר את מצב שרת המעבדה
python3 tracks/backend/rest-contracts/client.py

# באישור מפורש: יצירת משימה סינתטית, התנגשות גרסאות, עדכון ומחיקה
python3 tracks/backend/rest-contracts/client.py --demo
```

הלקוח פונה לכתובת loopback בלבד. מצב `--demo` יוצר משימה עם תוכן סינתטי, מבצע `GET`, מדגים שגיאה `412 Precondition Failed` עבור גרסה מיושנת, מעדכן עם גרסה נכונה ומנסה למחוק את המשימה שנוצרה. כל המידע נשאר בזיכרון המקומי של התהליך. `Ctrl+C` סוגר את שרת המעבדה.

## 3. ממשק ה־API

| Method | Path | Response | Purpose |
| --- | --- | --- | --- |
| GET | `/health` | 200 | Health מקומי ללא מידע אישי |
| GET | `/tasks?offset=0&limit=20&done=false` | 200 | רשימת משימות עם סינון ועימוד |
| GET | `/tasks/1` | 200 + `ETag` | קריאת משימה בודדת וגרסתה |
| POST | `/tasks` | 201 + `Location` + `ETag` | יצירת משימה חדשה |
| PATCH | `/tasks/1` | 200 + `ETag` | עדכון חלקי בתנאי שהגרסה מתאימה |
| DELETE | `/tasks/1` | 204 | מחיקה בתנאי שהגרסה מתאימה |

לדוגמה:

```bash
curl -i http://127.0.0.1:8765/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Learn HTTP status codes","done":false}'

curl -i http://127.0.0.1:8765/tasks/1

# השתמשו בערך ETag המדויק שהתקבל ב-GET; למשל "task-1-v1".
curl -i -X PATCH http://127.0.0.1:8765/tasks/1 \
  -H 'Content-Type: application/json' \
  -H 'If-Match: "task-1-v1"' \
  -d '{"done":true}'

# כעת ETag השתנה; שימוש בערך הישן יידחה.
curl -i -X PATCH http://127.0.0.1:8765/tasks/1 \
  -H 'Content-Type: application/json' \
  -H 'If-Match: "task-1-v1"' \
  -d '{"title":"Stale update"}'
```

**קודי שגיאה:** `400` גוף JSON/פרמטרים פגומים; `403` Host או Origin שאינם loopback; `404` משאב לא קיים; `409` מכסת משימות; `412` ETag אינו מעודכן; `415` Content-Type אינו JSON UTF-8; `428` בקשת שינוי ללא `If-Match`.

גוף `POST` מחייב `title` לא ריק (עד 120 תווים אחרי קיצוץ רווחי קצה), ויכול לכלול `done` בוליאני. `PATCH` חייב לכלול לפחות אחד משני השדות. שדות לא ידועים, JSON עם מפתחות כפולים, `NaN`, מחרוזות לא תקינות, בקשה מעל 8 KiB וערכי בוליאני שאינם JSON `true/false` נדחים. המזהים מוקצים באופן עולה בכל הרצת שרת.

לעימוד: `offset` נע בין 0 ל־100000; `limit` בין 1 ל־50; `done` מקבל רק `true` או `false`. סדר הרשומות הוא לפי מזהה עולה, ומוחזרים `total`, `offset`, `limit` ו־`items`. אין snapshot עקבי בין שתי בקשות שונות בזמן שמתרחשים שינויים.

## 4. תרגיל עצמאי

1. צרו שתי משימות באמצעות `POST` ובדקו את `Location` וה־`ETag` של כל אחת.
2. בצעו `GET` לקבלת גרסה, ועדכנו פעם אחת באמצעות `PATCH`.
3. נסו לשלוח שוב `PATCH` עם ה־ETag הישן. הסבירו למה התגובה היא `412` ולא `409`.
4. בצעו `DELETE` ללא `If-Match` והשוו לתגובה שניתנת לאחר משלוח ה־ETag המעודכן.
5. בדקו עימוד וסינון בעזרת `offset`, `limit`, `done`; הסבירו מה קורה אם בקשה אחרת יוצרת משימה בין דפים.
6. הציעו איך הייתם משנים את השירות לעבודה מרובת משתמשים, לאחסון קבוע, ולניהול הרשאות בצד השרת.

**חשוב:** `ETag` כאן הוא מזהה גרסה מקומי, לא חתימה קריפטוגרפית, ולא מחליף אימות משתמש או הרשאות. השימוש ב־`ThreadingHTTPServer` ובהגנה באמצעות `Lock` מאפשר להדגים עדכון מותנה אטומי בתהליך יחיד; הוא אינו מבטיח זמינות, durability, הגנה מפני מתקפות, scaling או מערכת נעילות מבוזרת. הגבלת Host/Origin וממשק loopback מצמצמים חשיפה מקרית, אך אינם הופכים את השירות לבטוח לפריסה ציבורית.
